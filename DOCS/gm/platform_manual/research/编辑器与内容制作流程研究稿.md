# GM 平台编辑器与内容制作工作流研究稿

> 用途：供最终《GM 平台技术说明书》引用，面向在 GM 上搭建具体游戏的开发者。本文来自当前仓库源码、正式 Resource、样板、测试和封存报告的只读扫描；不是对所有界面做过真人可用性验收的声明。

## 1. 结论先行：开发者应怎样理解 GM

GM 不是一个把玩法写死在场景节点里的“游戏模板”，而是一组 Godot 4 Resource、稳定业务 ID、模块 Manifest、领域服务和编辑器 Dock。推荐的制作顺序是：

1. 选择空间模式和启用模块；
2. 建立项目 Profile、Manifest Index 和各模块 Manifest；
3. 用 `.tres` Resource 定义内容，不以 NodePath、中文名或文件路径充当业务身份；
4. 制作地图/Surface Graph、语义对象、角色、设施与 Process、Task、能力和事件；
5. 用正式 Dock 的“应用”按钮提交到 `EditorUndoRedoManager`，先验证，再保存并关闭重开；
6. 由正式入口组装 PlayerShell、SimulationWorld、Store、Task/Planner/Ability/Process 链；
7. 用 CLI、Dock 校验和真实导出候选做发布前检查。

权威数据通常是 Resource 内的声明数组或领域 Store；编辑器显示值是投影。例如中性纵向样板中的 NPC 数量只读自 `actor_specs.size()`，不得另造一个可写 `npc_count` 权威。

当前已验证运行基线是 Godot `4.6.2-stable official`。`4.7.2` 只是未来兼容目标，未执行验证。

## 2. 启动编辑器与找到工具

主插件入口为：

- `addons/gm_editor/plugin.cfg`：插件名“GM平台编辑器”；
- `addons/gm_editor/plugin.gd`：创建各 Dock、Inspector 和 ExportPlugin；
- `project.godot`：当前启用 `gm_editor`、`gm_agent_planner`、`TileMapDual`、`gut`、`gm_feedback`、`gm_p26_vertical_sample` 六个插件。

从零使用：

1. 用 Godot 4.6.2 打开工程；
2. 在“项目设置 → 插件”确认 `GM平台编辑器` 已启用；
3. 在编辑器底部面板切换 GM 工具；默认打开“GM策划工作台”；
4. 若面板未出现，先看 Godot Output 是否有 `workbench_enter`，再查脚本解析、插件依赖与缺失 Resource；不要在插件未成功注册时继续录入数据。

`plugin.gd` 实际注册的主要面板如下：

| 面板 | 主要用途 |
|---|---|
| GM策划工作台 | 综合状态、通用策划工作流与错误中心 |
| GM内容资源库 | GMContent 扫描、筛选、引用影响、删除保护、内容类型向导 |
| GM地图工作台 | 2D 方格/等距地图、逻辑/表现层和画笔 |
| GM语义地图 | 区域、路线、锚点、Portal、Camera2D 区域 |
| GM对象装配 | 把对象定义拖入地图并装配交互、Owner、身份和锚点 |
| GM角色资产库 | 2D 角色 Definition/VisualSet、动作、方向、锚点和事件帧 |
| GM角色NPC装配 | 2D 角色外观、RoleProfile、碰撞与地图锚点装配 |
| GM移动能力 | 方向/直达/锚点/跟随/巡逻/朝向/取消/旅行配置 |
| GM任务工作台 | Task、Objective、Assignment、DutyProvider、Reservation |
| GM能力浏览器 | GameplayTag 分组、搜索、能力资源浏览 |
| GM事件触发器 | GameplayEvent Trigger 与 Godot 局部 Signal 两类图的审计 |
| GM平面3D地图 | Surface Graph 和 Connection CRUD、Gizmo 预览 |
| GM 三维场景配方策划 | SceneRecipe3D 的世界对象、设施、入口、WorkSpot 摆放 |
| GM角色3D视觉 | 3D Recipe、骨骼/Socket、FitClass、共享动作与导入元数据 |
| GM角色3D装配 | 3D Body/Head/Hair/Outfit/Feature/Palette 装配与缓存 |
| GM平面战斗与Cue3D | Attack/HitVolume/目标/高度容差和命中查询 |
| GM渲染风格与材质 | 低分辨率 World、原生 UI、Lighting/Dither/Shadow/Pose |
| Planar 3D中性纵向样板 | 编辑纵向样板名称、NPC 声明并保存重开 |
| GM三维预算与验证 | 三维资源预算检查、错误定位、派生缓存修复 |

另有 `gm_agent_planner`、`gm_feedback`、`gm_p26_vertical_sample` 独立插件面板；它们分别提供 Planner、反馈链和 P26 样板入口，不应取代正式领域 Resource。

## 3. 从零搭建一个游戏的推荐流程

### 3.1 选择 2D-only 或 Planar3D-enabled

模块选择是交付边界，不是运行时随意开关。

- 2D-only：`core`、`spatial.core`、`spatial.planar_2d`；不应包含 `gm_runtime/map/3d`、`gm_adapters/spatial3d`、3D 角色/渲染/战斗根。
- Planar3D-enabled：在上述基础上启用 `spatial.planar_3d`、`character.visual_3d`、`scene.execution`、`presentation.render_style_3d` 和纵向样板模块。

真实参考：

- 3D Manifest Index：`gm_runtime/manifests/gm_ext_3d_11_manifest_index.tres`；
- 2D Manifest Index：`gm_runtime/manifests/gm_ext_3d_11_2d_manifest_index.tres`；
- 3D 正式入口：`gm_runtime/vertical_sample/gm_ext_3d_11_entry.tscn`；
- 2D 正式入口：`gm_runtime/vertical_sample/gm_ext_3d_11_2d_entry.tscn`；
- 发布裁剪规则：`export_presets.cfg`。

不要在一个发行候选里“顺便带上”另一模式。2D 导出 preset 明确排除 3D 根、3D Manifest 和 3D 正式入口。

### 3.2 配置 Project Profile 与 Manifest

项目模块 Profile 类型是 `GMProjectProfile`（`gm_runtime/gm_project_profile.gd`），真实字段：

```gdscript
template_id = "blank_2d"
enabled_modules = PackedStringArray(["core", "spatial.core", "spatial.planar_2d"])
spatial_domain_id = "gm.spatial.planar_2d"
spatial_backend_id = "gm.spatial.backend.planar_2d"
spatial_backend_enabled = true
```

基础资源在 `gm_runtime/gm_module_profile.tres`。模块清单类 `GMModuleManifest` 的可配字段包括：`module_id`、`version`、中英文说明、`runtime_root`、`editor_root`、必需/可选模块、冲突模块、content types、abilities、effects、events、cues、tags、runtime services、service implementations、spatial backends、editor entries、导出必须/排除路径、validation rules、migrations、license、release security、native dependencies 和 private build artifacts。

Manifest Index 只有两个核心字段：

```gdscript
index_version = "1.0.0"
manifest_paths = PackedStringArray([
  "res://gm_runtime/manifests/core.tres",
  "res://gm_runtime/manifests/spatial_core.tres",
  "res://gm_runtime/manifests/spatial_planar_2d.tres"
])
```

使用规则：

1. 每个模块一个 Manifest；稳定 `module_id` 不随目录或中文名变化；
2. 在 Index 中显式列出 Manifest 路径；
3. 让 Registry 解析依赖、冲突、服务和空间后端；
4. 导出时同时遵守 `export_required_paths` 和 `export_excluded_paths`；
5. 关闭模块时验证依赖者，不要只删目录。

### 3.3 复制样板，而不是把样板身份当成自己的身份

Planar3D 可从 `gm_runtime/vertical_sample/gm_ext_3d_10_profile.tres` 复制。其类型是 `GMNeutralVerticalSampleProfile`，Schema 为 `gm.neutral_vertical_sample.profile.v3`。复制后至少整体替换：

- `profile_id`、`map_id`、`graph_id`；
- `entry_surface_id`、`scene_definition_id`、`scene_recipe_id`；
- 玩家与工作流 `task_definition_id`；
- `player_target_workspot_id`、`attack_id`；
- `actor_specs` 中全部 actor/entity ID；
- `facility_specs` 中 Facility、WorkSpot、Anchor、Reservation、Process、Resource、Account ID；
- `surface_specs`、`connection_specs`；
- `save_path`，且必须位于 `user://`。

最小示例：

```gdscript
profile_id = "mygame.profile.harbor"
map_id = "mygame.map.harbor"
graph_id = "mygame.graph.harbor"
entry_surface_id = "mygame.surface.harbor.courtyard"
actor_specs = [{
  "actor_id": "mygame.actor.harbor.worker.01",
  "entity_id": "mygame.entity.harbor.worker.01",
  "spawn_logical": {"x": 5.0, "y": 10.0},
  "target_workspot_id": "mygame.workspot.harbor.workshop.main"
}]
save_path = "user://mygame_harbor.world.json"
```

正式入口支持参数覆盖：`--gm-ext-3d-10-profile=res://path/to/profile.tres`。路径必须是 `res://`，加载后会执行严格 `validate()`。编辑器中性样板 Dock 也可通过环境变量 `GM_EXT_3D_10_EDITOR_PROFILE_PATH` 指向明确 Profile；显式目标不存在或类型错误时应 fail-closed，不回退误写默认 Profile。

## 4. 地图与空间内容

### 4.1 2D 地图工作台

打开“GM地图工作台”，选择“方格样板”或“等距样板”。面板显示 `GMMapResource.layers` 中的真实图层；当前设计是三表现层加一逻辑层，并显示类型、顺序、锁定和可见性。使用“画笔绘制”，再用“撤销/重做”。图例：绿色可通行、红色不可通行、金色为本次画笔结果、深蓝为空单元。

TileMapDual 后端不可用时面板进入只读状态，绘制被禁用且地图 Resource 不应被改写。不要绕过此保护直接改面板内部状态。

### 4.2 语义地图

“GM语义地图”负责把纯地形变成玩法可引用的语义对象。标准步骤：

1. 在“地图稳定 ID”输入如 `mygame.map.harbor`，点击“新建”；
2. 选择对象类型：区域、路线、锚点、Portal、Camera2D 区域；
3. 点击“新增”，填表后“应用编辑”；
4. 需要时在画布中使用选择/移动/加点；
5. 点击“一键验证”；
6. 填 `res://.../*.tres`，点击“保存”；
7. 用“关闭”后“打开路径”验证重开。

通用操作还有复制、删除、路线反转、闭环切换、撤销、重做和“从所选锚点测试”。测试启动参数是 ephemeral，保存时会剔除，不应污染正式存档。

真实字段：

- Region：稳定 ID、`polygon` 点串 `x,y;…`、tags、priority、重叠规则 `STACK/HIGHEST_PRIORITY/EXCLUSIVE`、enter/exit event tag、camera config ID；
- Route：点串 `x,y|speed|wait|anchor|map;…`、closed、allowed movement types；
- Anchor：类型 ID、位置、朝向、容量、tags、编辑器显示名；显示名可变，稳定 ID 不随节点重命名而变；
- Portal：源/目标 map 与 anchor、return anchor、单向/双向、required ability、loading parameters JSON；
- Camera2D zone：`x,y,w,h`、zoom、`lock_on/smooth_follow/room_center`、target role、priority、pixel-align placeholder。

最小 Portal 例：

```text
id=mygame.portal.harbor.to_market
source_map=mygame.map.harbor
source_anchor=mygame.anchor.harbor.exit
target_map=mygame.map.market
target_anchor=mygame.anchor.market.entry
direction=双向
required_ability=mygame.ability.open_gate
loading={"transition":"fade","spawn_facing":180}
```

### 4.3 Planar3D Surface Graph

打开“GM平面3D地图”。顶部输入 Graph Resource 路径和中文名，可“保存 Graph”“关闭并重新打开”“应用名称编辑（可撤销）”“中文校验”。

Surface CRUD 字段：

- 稳定 ID、中文名；
- 类型：`courtyard/floor/bridge`；
- XZ 边界：`0,0;10,0;10,8;0,8`；
- 世界原点 `x,y,z`、高度斜率 `x,y`、最大坡度；
- Agent Profile 列表；
- 可选语义 Region ID。

Connection CRUD 字段：

- 稳定 ID、源/目标 Surface；
- 源出口、目标入口；
- 类型：`stairs/ramp/bridge/portal/door/lift_reserved`；
- 方向：`source_to_target/target_to_source`；
- Agent Profile、通行成本、可选 required ability ID。

所有成功 CRUD 应进入 `EditorUndoRedoManager`，无效稳定 ID、非法点串、悬空 Surface 引用等必须拒绝且保持旧值。右侧 3D 预览、Surface 颜色和 Connection 线是编辑器投影，不是第二份地图数据。

### 4.4 SceneRecipe3D 世界对象与设施摆放

打开“GM 三维场景配方策划”。流程：

1. “新建中性场景”；
2. 从对象面板拖 `building/facility/npc_spawn/entrance/workspot/semantic_slot/navigation_anchor` 到三维视口；
3. 选择网格、平面、旋转、插槽、地面等吸附选项；
4. 在当前摆放列表选择对象，使用操作手柄；
5. “中文校验”后“保存场景”；
6. “关闭并重新打开”验证；
7. 派生缓存异常时先“删除派生编译缓存”，再“重建编译缓存”。

摆放记录包含 `stable_id`、kind、中文名、surface/profile/socket/semantic reference、position、rotation、scale。新 ID 从当前文档的 `scene_business_id/document_id/recipe_id` 命名空间派生，禁止所有项目共享固定样板前缀。

## 5. 内容、对象、角色和 NPC

### 5.1 内容资源库和 Registry

GitHub 清洁发布版的“GM内容资源库”扫描 `res://gm_runtime/content`，展示中文名、业务 ID、类型、标签、引用状态、文件路径和缩略图。可按中文名/ID/类型搜索，按类型、标签、被引用/未使用、是否废弃过滤，并切换表格/卡片。源仓库内部开发样板目录不随本清洁版提供。

开发者使用顺序：

1. “重新索引”；
2. 选择资源查看正向/反向引用；
3. 用“定位文件”进入原生 Inspector；
4. 修改/删除前先做“影响分析”和“删除保护检查”；
5. 批量选择只提供“批量只读查看”，不是批量改写；
6. 新领域类型用“新内容类型向导”，向导生成可编辑 GDScript、类型注册 Resource、验证器、列表入口和测试模板。

`GMContent` Resource 才是唯一事实源。业务 ID 与路径、ResourceUID 分离；路径移动不能偷偷改业务身份。项目内容不要占用平台保留的 `gm.*` ID 前缀，应使用自己的命名空间。

### 5.2 对象装配

“GM对象装配”从内容对象库拖定义到地图，自动装配 Owner、稳定实例 ID、GAS 交互、保存身份和锚点。可用操作：复制（生成新 ID）、删除、撤销、重做、修复预览、应用修复、运行交互。

原则：预览修复不写正式对象；“应用修复”才提交。运行交互需要正式 Object Definition/Ability 链，不可把按钮返回文本当成事务已提交。

### 5.3 2D 角色资产

“GM角色资产库”有四组主要工作：

1. 角色库：按名称、稳定 ID、画风、类别、标签、完整度搜索；“扫描/校验”。“1500角色有界夹具”是容量测试，不是游戏内容生成器。
2. 导入与保存：填写 Definition ID/名称、VisualSet ID/名称、导入源、两个保存路径；支持帧目录、SpriteFrames、VisualSet 或 Definition。帧命名为 `semantic_direction_000.png`，语义至少覆盖 `idle/move/attack/hurt/death`，方向模式为 `one/four/eight/four_mirrored`。Aseprite 只是可选 Adapter。
3. 动作与方向：为五语义动作设置方向规则、是否镜像、`direction=animation` 映射；通过正式按钮一次提交全部动作。
4. 锚点与事件帧：按动作/方向/帧设置锚点坐标，或增加事件名、事件类型、帧号。越界、重复或超过帧数会结构化失败，不写原资源。

保存必须让 Definition 引用外部唯一 VisualSet：先另存 VisualSet，再保存 Definition，然后用 `CACHE_MODE_IGNORE` 重开并确认解析到同一路径。两个路径必须是不同的 `res://...tres`。

### 5.4 2D NPC 装配

“GM角色NPC装配”要求三类输入齐全：Character Definition/VisualSet、RoleProfile、Shape2D。也可拖入已装配 PackedScene。然后：

1. 打开一个实际 2D 地图场景；
2. 填地图稳定 ID 和任务09语义出生锚点；
3. 填 `res://...tscn` 保存路径；
4. “装配到当前场景”；
5. 用“撤销装配/重做装配”检查 Owner 和可见性；
6. “保存角色场景”。

如果当前没有编辑场景、资源类型不符、地图/Anchor 无效或路径不是 `res://*.tscn`，操作会拒绝。这里装配的是 2D Runtime Character；移动、Reservation 和行为调度分别由后续移动、Task、Planner/策略模块负责。

### 5.5 3D 角色视觉与装配

“GM角色3D视觉”配置 Recipe ID/名称、Body/Head/Hair/Outfit/Feature/Accessory、Posture、Skeleton、Animation Profile 和保存路径。还可配置外部骨骼名到 canonical bone、Socket ID/允许槽位、FitClass、语义动作、共享 Animation、导入源类型/指纹/路径。标准流程是扫描 Registry → 加载中性 Recipe → 应用引用 → 校验 Skeleton/Socket、FitClass/Outfit、共享动作和导入边界 → 保存 → 关闭/重开。

“GM角色3D装配”进一步指定 Actor ID 与玩家/固定 NPC 类型，应用 Outfit/材质、Body Hide、Palette、Feature 增删，并提供“编译/命中缓存、重建缓存、删除缓存”。缓存是派生物，可删可重建；Recipe 和稳定 ID 才是权威。

## 6. 移动、设施、Process、Task、能力与交互

### 6.1 移动配置

“GM移动能力”支持 `direction/direct/anchor/follow/patrol/face/cancel/travel`。公共参数是 speed、acceleration、stop distance、follow distance；语义目标包括 map、anchor、follow actor、patrol route 和 loop；旅行交接包括 target map、entry/exit/return anchor。

点击“应用到移动配置”会原子更新 `GMMovementProfile`，然后保存、撤销/重做。Travel 只声明跨地图交接，不自行创建 SceneSession。

### 6.2 Facility / WorkSpot / Process

当前最具体的制作范式在 `gm_neutral_vertical_sample_profile.gd`。Facility 的 `workspots` 每项必须完整声明：

```gdscript
{
 "workspot_id":"mygame.workspot.harbor.workshop.main",
 "anchor_id":"mygame.anchor.harbor.workshop",
 "surface_id":"mygame.surface.harbor.bridge",
 "logical_position":{"x":25.0,"y":10.0},
 "capacity":10,
 "reservation_rule_id":"mygame.reservation.workshop",
 "process_definition_id":"mygame.process.workshop.craft",
 "resource_id":"mygame.resource.supply",
 "resource_account_id":"mygame.account.workshop.supply",
 "resource_initial_balance":10,
 "resource_recovery_balance":10,
 "resource_amount_per_process":1
}
```

`GMProcessDefinition` 字段为：`definition_id`、revision、中文名、process family、duration units、capability IDs、facility target、completion kind/payload、task definition ID、duty provider ID。completion kind 当前允许 `none`、`p19_transaction`、`typed_domain_request`。

约束：WorkSpot 的 Surface 必须存在；capacity ≥ 1；资源余额非负且恢复余额足够；WorkSpot/Anchor/Process/Resource/Account ID 不重复；角色只引用已声明 WorkSpot。

### 6.3 Task 工作台

“GM任务工作台”统一管理 TaskDefinition v2、Objective、Assignment、DutyProvider 和 Reservation。核心操作顺序：

1. 填 Task Definition ID、中文名/说明；
2. 填 Objective ID、中文名，选择推进信号 `fact/change/cue`，填匹配的 `gm.fact.* / gm.change.* / gm.cue.*` 类型、目标值与资源 ID；
3. 选择发布来源：player/ai/organization/world_event/script/duty_provider；
4. 选择上下文：local/summary/scene（scene 只声明上下文）；
5. 填 Task instance、可选 parent、Assignment ID、assignee kind/type/id；
6. 配 Reservation rule、subject、exclusive/capacity、容量、实例 ID、数量和逻辑到期 tick；
7. 配 DutyProvider ID、事件类型、幂等键字段与 subject；
8. 依次“应用修改”→“保存资源”→“注册定义”→“发布Task”→“建立分配”→“注册职责Provider/取得Reservation”。

所有执行统一进入 Ability → Resolver → Transaction，并提交 Fact/Change/Cue；工作台不直接写角色、地图或物品。Objective 只消费权威 Store 中已提交事件。v1 Objective 不能无歧义迁移为 v2，会明确拒绝，需人工重存。

### 6.4 能力与 GameplayEvent

“GM能力浏览器”可按 GameplayTag/别名搜索和按分组过滤，也能创建标签（例如 `animal.behavior.forage`）。稳定标签应作为机器值，中文仅用于显示。

“GM事件触发器”把两类关系严格分开：

- GodotLocalSignal：场景内 Callable 连接，可持久或仅运行时；
- GameplayEvent：event tag/schema → condition → target selector → ability/handler。

面板支持重新发现、真实 EditorSelection/Inspector 定位、连接/断开局部信号和 Undo/Redo 连接探针。示例包括死亡→掉落、进入区域→开门、生产完成→任务更新。正式流水线是 `GMGameplayEventTrigger -> GMAbilitySystemHost -> GMAbilityActivationRequest -> 事务/Fact/EventStore`。

## 7. 正式入口、保存恢复和调试

### 7.1 运行入口

开发期直接运行相应正式 `.tscn`，不要用测试 fixture 或 Dock probe 当游戏入口。当前最高阶参考是：

- Planar3D：`res://gm_runtime/vertical_sample/gm_ext_3d_11_entry.tscn`；
- 2D-only：`res://gm_runtime/vertical_sample/gm_ext_3d_11_2d_entry.tscn`。

3D 正式导出 preset 在 `export_presets.cfg` 指向 EXT11 entry/profile/budget/profile shell/manifest index；2D preset 有明确排除清单。发布前必须从当前源码重新导出并冷启动，不要只比较文件大小。

### 7.2 保存/恢复合同

当前世界文件 Schema 是 `gm.simulation_world.v6`，Store snapshot 是 `gm.store_snapshot.v3`。正式恢复链是 PlayerShell → SimulationWorld → GMStore：先构建 Profile/Shell 与语义锚点，再恢复；在 detached 状态完整验证后才原子 commit。

开发者必须验证三种情况：

1. 无存档首次启动正常；
2. 保存退出后，第二个独立进程普通启动恢复；
3. 损坏或旧 Schema 存档被拒绝，live world 和 Store 不部分改变。

当前迁移合同不承诺缺失 `visual_recipe_id`、`facing` 等字段自动重建，也不承诺全历史 Schema 自动迁移。

### 7.3 CLI 与诊断入口

GitHub 清洁发布版的 Windows 入口为 `gm_cli.cmd`，它调用 `gm_cli_launcher.py` 和 `gm_cli.gd`。发布版实际提供五个只读命令：

```cmd
gm_cli.cmd help
gm_cli.cmd environment
gm_cli.cmd compatibility
gm_cli.cmd validate
gm_cli.cmd modules
```

源仓库内部的测试、插件冒烟、导出冒烟和模块专项验收依赖测试树或审查环境，不随 GitHub 清洁发布版提供。遇到错误时按层定位：

- 插件未加载：看脚本 Parse error、preload 缺失、`workbench_enter`；
- 地图不可编辑：查 TileMapDual 健康状态；
- Resource 不入库：查业务 ID、类型注册、损坏隔离和 Registry issue；
- 编辑失败但显示没变化：确认 `EditorUndoRedoManager` 存在、操作是否真正 commit；
- 保存后没恢复：必须用独立新进程和同一 `user://` 根验证；同进程 `CACHE_MODE_IGNORE` 重载不等于跨进程恢复；
- 3D 内容异常：先校验稳定引用，再删/重建派生缓存；
- 导出缺内容：对照 Manifest required/excluded paths 和选定模块模式。

## 8. 常见错误与安全做法

1. **把中文名当 ID**：中文名可改；引用必须用合法稳定 ID。
2. **复制样板但保留 `ext3d10` 身份**：会污染另一 Profile。全量换命名空间，并用非默认 Profile 保存/独立重开。
3. **显式目标加载失败后回退默认资源**：禁止；应保留请求路径、清空目标并 fail-closed。
4. **直接写派生计数**：如 NPC 数量必须通过 `actor_specs` 增删，计数仅投影。
5. **只看按钮成功文字**：还要验证 Resource 值、事务返回、保存文件和独立重开。
6. **绕过 Undo/Redo 直改 Resource**：正式 Dock 修改必须经过 `EditorUndoRedoManager`；失败保持旧值。
7. **把缓存当源码**：`.godot` 和视觉编译缓存均可重建，不进内容权威或复制归档。
8. **2D 包夹带 3D**：按 preset/Manifest 做完整 inventory，而不是只看入口能否启动。
9. **NodePath 充当业务身份**：场景节点可移动/重命名；用 business ID 和 SceneReference/EntityReference。
10. **测试运行污染正式保存**：语义“从锚点测试”等 ephemeral 参数不得写入正式存档。
